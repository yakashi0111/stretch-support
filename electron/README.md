# Stretch Tool — Mac アプリ (Electron)

リポジトリ直下の `index.html`（Web版と共通）を Mac のアプリウィンドウとして動かします。
ミニ表示にすると、YouTube などの全画面の上に小さなタイマーを重ねられます。

## 起動（開発時）

Node.js 18 以上が必要です。

```bash
cd electron
npm install
npm start          # index.html を renderer/ へコピーしてから起動
```

## .app のビルド

Mac 上で実行します（Apple Silicon 用）。

```bash
cd electron
npm install
npm run build      # → dist/Stretch Tool-darwin-arm64/Stretch Tool.app
```

- Intel Mac 用: `npm run build:intel` / 両対応: `npm run build:universal`
- 開発者証明書なしの ad-hoc 署名を自動で付けます（App Store 申請や公証は対象外）。
- 完成した `.app` を「アプリケーション」フォルダへドラッグして使います。
- 初回起動で「開発元を確認できません」と出たら、`.app` を右クリック →「開く」。それでも開けない場合:
  `xattr -cr "/Applications/Stretch Tool.app"`

## 使い方

- タイマー画面の右上の **「ミニ」** ボタンで、小さな最前面ウィンドウ（320×150）に切り替わります。ボタンは **「通常」** に変わり、押すと元のウィンドウサイズ・位置に戻ります。
- ミニ表示では、種目名・残り秒数（一番大きい）・全体の進捗・次の種目を表示します。**秒数をクリック**すると開始／一時停止します。ウィンドウの余白をドラッグすると移動できます。
- グローバルショートカットは一切登録していません（YouTube の Space キーなどを奪いません）。アプリ内のキー操作は、アプリがアクティブな間だけ働きます。
- ミニ表示の間だけ最前面です。通常表示に戻すと解除されます。ミニ中は最小化・拡大ボタンを無効にしています（ダブルクリックでの誤操作防止）。

### ウィンドウ位置の扱い

- 初回のミニは、今いる画面の右上（メニューバー・ノッチの下）に開きます。次回からは前回置いた位置です。画面の外にはみ出さないよう収め直します。
- 通常に戻すとき、ミニを動かしていなければ **切替前の位置とサイズへそのまま** 戻ります。ミニを動かしていた場合は、元の位置へ飛ばさず **今の位置から広げ**、画面からはみ出す分だけ内側へ寄せます。

## データの保存

ルーティーンは `~/Library/Application Support/Stretch Tool/stretch-data.json` に保存されます（直前の版は `.bak`）。アプリを終了・再起動しても残ります。
このファイルを消さない限り、ビルドし直しても保持されます。

## Chrome などに保存済みのルーティーンを移す

ブラウザの保存データは Electron 版から直接は読めないため、アプリの **バックアップ／取り込み** で移します。既存のデータは **上書きも削除もされません**（取り込んだルーティーンは追加されます）。

1. ブラウザで、これまで使っていた Stretch Tool のページ（GitHub Pages など。最新版に更新されています）を開きます。古い版のデータは、最新版を開くと自動で引き継がれます。
2. ホーム画面の下の **「すべてのルーティーンをバックアップ」** を押し、**「コードをコピー」**（または **「ファイルに保存」**）。
3. Mac アプリのホーム画面で **「取り込み」** → コードを貼り付け（またはファイルから読み込み）→ **「取り込む」**。

移せないとき（ブラウザ側が開けない等）は、ルーティーンごとに「…」→「ルーティーンを共有」のコードでも移せます。

## 安全設定

`contextIsolation: true` / `nodeIntegration: false` / `sandbox: true`。preload が公開するのは次の3つだけです（`preload.js`）。

| 関数 | 用途 |
|---|---|
| `loadDataSync()` / `saveData(text)` | ルーティーンデータの読み書き |
| `setMini(on)` | ミニ表示 ⇄ 通常表示（サイズ変更・最前面の切替） |

外部ページへの遷移・新規ウィンドウはブロックし、ページは外部通信しない CSP で動きます。

## YouTube 全画面への重ね表示について（実機で要確認）

ミニ表示では `setAlwaysOnTop(true, 'screen-saver')` と `setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })` を使います。
**この重ね表示は macOS 実機でしか確認できず、開発環境（Linux）では動作確認できていません。** 次の組み合わせで確認してください。

| YouTube の状態 | 期待 |
|---|---|
| Chrome の全画面（緑ボタン／Fキー） | ミニが全画面の上に出る |
| Safari の全画面 | 同上 |
| 通常ウィンドウ表示 | ミニが YouTube ウィンドウの前面に出る |
| 別の Space（デスクトップ）にいる | ミニが全 Space に出る |

既知の注意点・回避策:

- ミニ表示の間は Dock のアイコンが消えます（macOS 上での Electron の仕様）。通常表示に戻すと復帰します。
- ミニをクリックするとアプリがアクティブになり、設定によっては別の Space へ切り替わることがあります。システム設定 →「デスクトップとDock」→「アプリケーションの切り替え時、そのアプリケーションの開いているウィンドウがあるSpaceに切り替える」をオフにすると防げます。
- ミニが全画面の上に出ない場合は、`main.js` のウィンドウを `type: 'panel'`（NSPanel）で作る方式に変えると改善することがあります。
- YouTube の再生・停止は YouTube 側で操作してください（ミニの操作とは独立です）。

## テスト

```bash
cd electron
npm test           # ミニ表示の位置・サイズ・最前面切替のロジック (Electron 不要)
```

## ファイル

| ファイル | 役割 |
|---|---|
| `main.js` | ウィンドウ作成、データ保存（IPC）、メニュー |
| `mini-window.js` | 通常⇄ミニの切替ロジック（位置・サイズの保存と復元、最前面） |
| `preload.js` | レンダラーへ公開する最小限のAPI |
| `scripts/sync-renderer.js` | `../index.html` を `renderer/` へコピー |
| `scripts/adhoc-sign.js` | ビルド後の ad-hoc 署名（macOSのみ） |
| `test/mini-window.test.js` | ミニ切替ロジックのテスト |
